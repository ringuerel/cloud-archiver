## Brief overview
This set of guidelines outlines the preferred development workflow and communication style for this project, focusing on a Test-Driven Development (TDD) approach and clear, concise interactions.

## Development workflow
- **Test-Driven Development (TDD)**: New features or bug fixes should start with writing a failing test case that defines the desired behavior. The code is then implemented to make the test pass, followed by refactoring.
- **Iterative Changes**: Implement changes in small, logical steps. Each step should be verifiable and build upon the previous one.
- **Error Handling**: When an error occurs, analyze the stack trace and relevant logs to identify the root cause. Implement appropriate exception handling at the service and controller layers, and ensure tests cover these error scenarios.

## Communication style
- **Concise Responses**: Provide direct and technical responses, avoiding conversational filler (e.g., "Great", "Certainly").
- **Tool Use Explanation**: Clearly explain the purpose of each tool use and how it contributes to the task.
- **Task Progress Updates**: Regularly update the task progress checklist with each tool use to keep track of completed and remaining steps.
